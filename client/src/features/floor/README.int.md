# Floor plan, pixel view: notes for the integrator

Folder `client/src/features/floor/` + `client/src/locales/{en,az}/floor.json` (namespace `floor`). It replaces the body of `components/FloorPlanSheet.jsx`, which is now a thin wrapper with the same props (`restaurant`, `onClose`, `onReserve(table)`), so `RestaurantPage.jsx` needs no change.

**One-line edit (optional):** `lib/i18n.js`: `import floorEN from '../locales/en/floor.json'` (same for az) and `floor: floorEN` / `floor: floorAZ` in `resources`. Not required: `features/floor/i18n.js` self-registers the namespace when `mounts.js` is imported (the wrapper does that). CSS: `styles.css` (prefix `fl-`), imported by `mounts.js`. No routes, no nav.

**What it does.** Retro pixel map: SVG of whole-pixel square cells (28 columns, cell size = floor(width / 28), 6 to 14 px, fit to width, scrolls vertically). Tables are blocks with the number in DM Mono, seats are one-cell squares around each table, numbered clockwise from the top-left (seat n = the chair of QR `<code>-S<n>`). Taken seats are lit in the accent colour, free seats dim, the guest's own seat is gold. Section chips filter, the legend shows the states in view. Tap a table: number, state, seats free / total, the chairs, "Scan the QR on your chair to sit here". The plan never claims; a guest who already holds a session at that table (cart context `tableId`, not `pending`) sees "You're here" (with the seat from `my_table_session().seat_no`). A free table also gets "Reserve this table" when `onReserve` is passed (it was the old behaviour; the object has `id, table_number, capacity, state, sections.name`).

**Backend.** `floor_plan(p_restaurant_id)` (sql/49, anon ok). Layout: centres of `x,y,w,h` (100 x 64 canvas) are scaled to the grid, blocks never overlap (nudged to the nearest free spot, one cell of air), unplaced tables are packed in rows below, one row group per section. If the RPC is missing (`PGRST202`, 404) it reads the legacy `tables.pos_*` columns and shows no seat counts. Live: realtime on `tables` filtered by `restaurant_id` (never cross-tenant; the payload is not read, it only triggers a refetch), plus a 20 s poll and a refetch when the tab becomes visible, because seat changes at an already busy table do not touch the `tables` row.

**Not done / notes.** A pending guest holds a chair on the server (`occupied_seats` counts pending sessions) but sees "waiting for the host" instead of "You're here". Tables with more than 24 chairs draw 24. `prefers-reduced-motion` turns off the dashed selection march, the lit-chair pulse and the panel rise.
