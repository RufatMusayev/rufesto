# Restaurant page: Posts + a designed Menu (docs/V2-CONTRACT.md 19.2)

Why (Rufat, 2026-10-17): restaurants post like accounts, so the page opens on their posts; "the menu should look like a menu, not Insta postings", so the photo grid / list toggle is gone and the menu is a typographic card in the restaurant's own theme.

## Structure
`pages/RestaurantPage.jsx` (about 170 lines) is a shell: `RestaurantView` keyed by slug, tab + `?dish=` state, sheets. Everything else is here.

| File | What |
|---|---|
| `api.js` | every Supabase call (`fetchRestaurant`, `fetchMenu` with the PGRST202 fallback, `fetchRestaurantPosts`, seats, follow, promos, staff role, realtime subscribe helpers, `restoUrl`) |
| `mappers.js` | RPC / legacy rows -> view-model (`mapMenu`, `mapLegacyMenu`, `patchDish`, `findDish`, `toSheetDish`, `dishText`); dishes keep DB key names because `DishDetailSheet` and `CartContext.addDish` read them |
| `hooks.js` | `useRestaurant`, `useSeats`, `useFollow`, scroll memory for "back from a post" |
| `useMenu.js` / `usePosts.js` | one RPC per tab, cached per slug / restaurant+scope in memory (60 s / 90 s), keyset paging, dishes realtime (this restaurant only) |
| `RestaurantHeader.jsx`, `RestaurantTabs.jsx`, `CartErrorBanner.jsx`, `PageSkeleton.jsx`, `RestaurantNotFound.jsx` | page chrome. Sticky tab bar docks at `--sticky-top`. `RestaurantNotFound` is the page of an unknown / inactive slug |
| `PostsTab.jsx`, `PostTile.jsx`, `PromoStrip.jsx` | Posts: chips `From <venue>` / `Guests`, 3-column square grid, text tiles in the accent colour, promos from `public_ad_campaigns()`, manager link to the dashboard |
| `menu/MenuTab.jsx` (+ `MenuSection`, `MenuRow`, `SectionNav`, `MenuSearch`) | the printed menu; scroll-spy in `useScrollSpy.js`, search folding in `search.js`, contrast maths in `color.js`, cafe section icons in `icons.js` |
| `restaurant.css`, `menu/menu.css`, `menu/themes/{classic,bistro,modern,cafe}.css` | prefixes `rst-` / `mn-`. Themes only set `--mn-*` tokens under `.mn-wrap[data-menu="..."]` plus a few overrides; dark is the default and `[data-theme="light"]` overrides, like `index.css` |

Behaviour kept: Reserve, floor plan, Follow (sign-in then follow), stats, open state, `DishDetailSheet` (reviews, Add to order), cart errors, dish availability live. New: `?tab=posts|menu` (replace, no history spam); default tab = Menu for `?dish=` and for a guest seated here (decided once, waits for the cart's `tableReady`, max 1.5 s), else Posts; both tabs mount on first visit and stay mounted (no refetch, no re-render on switch).

## RPC shapes used (all verified on preview 2026-10-17 against the 10 seeded restaurants)
- `restaurant_menu(p_slug)` -> `{ restaurant{id,name,slug,logo,cuisine_type}, design{theme,accent,show_photos,note}, sections[{id|null,name,name_az,sort_order,dishes[{id,name,name_az,description,description_az,price,photo,available,is_vegan,is_vegetarian,is_gluten_free,is_spicy,spice_level,is_featured,avg_rating,review_count,prep_time_min,calories}]}], updated_at }`. Missing RPC (PGRST202 / 404) -> legacy `menu_sections` + `dishes` query, classic theme. Empty sections are not printed.
- `restaurant_posts(p_restaurant_id,p_cursor,p_limit)` and `restaurant_guest_posts(...)` -> `{ items[post 17.2], next_cursor }`; page size 21; `p_cursor` = previous `next_cursor`. A missing guests RPC shows the empty state. Photos are storage paths signed per page by `social/lib/postPhotos.js`.
- Also: `staff_role_at(p_restaurant_id)` (only to show "Post from the dashboard" to admin / manager, link built by `restoUrl('/posts')` = `resto.` + current host, no domain hardcoded), `public_ad_campaigns()` (promos, see below), `track_campaign`.

## QA fix round (docs/qa persona-leyla #1 #5 #19, persona-newcomer N01 N17 N20 N22; 2026-10-17)
- **Promo strip (#5)**: `fetchPromos` calls rpc `public_ad_campaigns()` (anon + authenticated; the `ad_campaigns` table is staff-only since sql/52, so the old select answered 401 signed out and `[]` signed in). The RPC returns every restaurant's campaigns, so the answer is cached 30 s and filtered here to `restaurant_id` + live (`status` active and inside `starts_at`..`ends_at`, see `isLivePromo`), at most two.
- **Unknown slug (N17)**: `fetchRestaurant` finds no row (or restaurant_not_found / PGRST116) -> `status 'missing'`; `restaurant_menu` raising restaurant_not_found -> `menuState.error.code`. Either renders `RestaurantNotFound` (strings `restaurant:notFound.*`) on the same URL; it no longer redirects Home.
- **Dish sheet (N01, N22)** `components/DishDetailSheet.jsx`: like, review and save call `requireAuth()` (`features/social/hooks`, the Home pattern) first: signed out opens the sign-in sheet and changes nothing (no local like, no burst, no write). The three actions are icon + word (`restaurant:dish.*`) with title and aria-label; saving toasts "Saved to your list" / "Removed from your list" (own `.dds-toast`, no dependency on the social styles).
- **QR scanner (#1)** `components/QRSheet.jsx` + `QRSheetScanner.js`: html5-qrcode 2.3.8 `stop()` throws a string synchronously when the scanner is not scanning (and "already under transition" when called while a stop is closing the camera); the success handler and the effect cleanup both stopped it and the throw unmounted the whole app. Now `stopScanner` (idempotent per scanner, try/catch, only stops SCANNING / PAUSED) is called from one place, the scanning effect's cleanup. A decoded code ends the run (`setScanning(false)`); a camera still opening when its run is torn down is stopped as soon as it started; the next run waits for the previous stop; one decode per run (no double `claim_table`); an unreadable code shows the error and the same camera run keeps looking; after the success screen the sheet closes and goes to `/table` (not when the caller passes `onCode`). Neither SPA has an error boundary: any other throw in render or a cleanup still blanks the page (App.jsx is not part of this change).
- **Prices and clock (#19)** `features/dinein`: the table page's dish lines are VAT-inclusive like the bill (`bill_lines.line_total` = net + VAT + service). `pricing.inclusiveLines(order)` shares the order's tax / service out by each line's part of the subtotal exactly as sql/42 does (per-line rounding, the remainder on the first line by created_at, cancelled items excluded); Subtotal / VAT / Total underneath are unchanged. The cart still lists menu (net) prices and then Subtotal / VAT / Total, as before. Times: `OrderCard` uses `formatBakuTime` (24-hour, Asia/Baku, whatever the browser locale); the receipt time forces `hourCycle: 'h23'`.
- **Notifications (N20)** `lib/notificationView.js`: a `bill_settled` payload with `restaurant_name` renders `notifications:bill_settled_at` ("Your bill at <name> is paid (...). Receipt ..."); without it the former text. Tap = `/receipt/<bill_id>` (falls back to `/restaurant/<restaurant_slug>` when there is no bill id). `restaurant_name` / `restaurant_slug` come from the database agent's change to that notification.

## Theme rules
Accent: `design.accent`, else classic `#8B2E1F`, bistro `#E0A100`, modern `#B23A3A`, cafe `#6B4A2B` (same as the dashboard preview). `color.js` derives a light-mode and a dark-mode accent per theme by pushing it to contrast >= 4.5 against that theme's paper (a dark red on the chalkboard becomes pink-red), set as `--mn-accent-l/-d`. Text on tinted fills uses ink, never the accent. Paper colours are duplicated in `color.js` (`PAPER`) and the theme CSS: change both.
Fonts: classic Playfair Display (+ small caps names, italic descriptions), bistro Barlow Condensed titles + DM Sans, modern DM Sans, cafe Nunito. `client/index.html` now also loads Barlow Condensed, Nunito and Playfair 400/500 + italics.
