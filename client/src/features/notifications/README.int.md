# Notifications v2 (consumer): integrator notes

> **UX round 4 (docs/UX-PLAN-2026-10-18.md section 2)**: the inbox is an Instagram-style activity list. No filter chips (`FilterChips.jsx` is deleted, `p_category` is never sent), no "Mark all read", no unread stripe / dot / count. Sections are **New / This week / Earlier** (rolling windows; New = unseen when the page opened, kept while it is open). Rows are 64 px: 44 px leading (one avatar, two offset 32 px avatars, the venue's avatar, or a line icon in a --s3 circle, never an emoji badge), the sentence with the actor / venue in bold and the short time (`lib/timeShort`) at its end, a 44 px thumbnail (`item.thumb`, sql/67). An incoming friend request (`actor_relation 'incoming'` + `friendship_id`) carries **Confirm / Delete** (`respond_friend_request`); `payload.status` accepted -> "is now your friend", declined / cancelled -> hidden. Dead targets: an old `order_ready` / no live table opens the receipt or the restaurant, `join_*` opens `/table` only while a table session is live. Opening the inbox zeroes the bell at once and marks the rows seen right after reading them; leaving it marks everything read. Pull to refresh. Copy has `<b>` around actor / venue (rendered by `richParts`, angle brackets of user values are dropped). Until sql/67: `seen` falls back to `read`, no `thumb` (payload photo keys still work), no inline buttons (`actor_relation` is missing). The sections below describe v2 as first built; where they mention chips, mark-all, Today / Yesterday or `unread`, this note wins.

Contract: `docs/V2-CONTRACT.md` section 21 (21.2 RPCs, 21.3 web push, 21.4 consumer). SQL (`sql/64`, `64b`) and the Edge Function are separate work; this feature runs without them (see "Before sql/64").

## Routes and entry points
- `/notifications`: the inbox (`NotificationsPage`, lazy in `App.jsx`; `pages/NotificationsPage.jsx` is gone).
- `/settings/notifications`: `PrefsPage` (`routes.jsx`, spread into `<Route element={<AppLayout/>}>` after `billsRoutes`). Linked from the inbox header (gear) and from Profile -> Settings ("Notification settings" row in `features/profile/components/SettingsSheet.jsx`; the existing "Notifications" row there still opens the inbox).
- `AppLayout.jsx`: `useNotificationBadge()` replaces the old count + channel (still ONE channel, still named `notif-badge`; the number goes to `Sidebar` as `unreadCount`) and `<NotificationsHost />` is mounted next to `CartFab`.
- `CartContext.placeOrder` (after `CLEAR`) and `BookGroupPage.submit` (after `setCreated`) each have ONE line: `import('.../notifications/prompt').then(m => m.maybeAskForPush('order'|'booking'))`.
- `index.html`: `<link rel="manifest">`, `apple-touch-icon`, a few `apple-mobile-web-app-*` / `mobile-web-app-capable` metas (`theme-color` was already there; `boot.js` keeps it in step with the theme).

## Files
- `api.js`: every call (`my_notifications`, `notifications_badge`, `mark_notifications`, `get/set_notification_prefs`, `save/delete_push_subscription`, plus two owner reads of `push_subscriptions`). Resolves `{ data, error }`, never throws. Maps the RPC's snake_case to items `{ id, ids, type, category, groupKey, count, actors[{id,name,photo}], at, read, payload, target }`.
- `lib/notificationView.js`: `describeItem(item, t, lang)` -> text / route / icon / tone / lead / thumb. Every type of section 21 and the older ones, en + az in `locales/{en,az}/notifications.json`. Route = the payload's own ids first (documented keys), else the server `target { kind, id, slug }`.
- `badge.js`: the bell number store + the realtime channel. `setInboxOpen(true)` (inbox mounted) sets the number to 0 (useInbox marks the rows seen after reading them); a row that arrives while the inbox is open re-reads the list and marks it seen again. `onInboxInsert(cb)` is how the page hears the channel (staff-audience rows are ignored).
- `useInbox.js`: the list (cursor paging, the "New" snapshot, optimistic read, Confirm / Delete, silent reload on insert). `useThumbUrls` signs `post-photos` paths (the bucket is private) through `social/lib/postPhotos`.
- `NotificationItem.jsx` / `Leading.jsx` / `InboxStates.jsx` / `SignedOut.jsx`: UI. `styles.css` (prefix `ntf-`), tokens only, no inline styles.
- `PrefsPage.jsx` + `usePrefs.js`: switches save as you tap (no Save button). Quiet hours always go as a pair (`quiet_from` + `quiet_to`, or both null), `HH:MM`.
- `push.js`: `pushSupport()` ('ok' | 'nokey' | 'ios_install' | 'unsupported'), `getPushState()`, `enablePush()`, `disablePush()`. `prompt.js` (`maybeAskForPush`), `PushPrompt.jsx` + `prompt.css`, `NotificationsHost.jsx`, `events.js` (kept tiny: it is in the entry bundle).
- `client/public/sw.js`, `manifest.webmanifest`, `apple-touch-icon.png`, `icons/{icon-192,icon-512,maskable-512,badge-72}.png` (rendered from `favicon.svg` with Chromium; `badge-72` is a white glyph on transparent for Android's status bar).

## Behaviour worth knowing
- **Badge** = `notifications_badge().guest_unseen`. Opening the inbox clears it without marking anything read (`seen` vs `read`). Re-read on realtime INSERT / UPDATE (300 ms debounce), on tab focus and when the tab becomes visible.
- **Inbox**: grouped items from the server; "Aysel, Nicat and 3 others liked your post" (first names once grouped, full name for one person). Tap = mark all `ids` of the group read, then navigate to the target. Sections Today / Yesterday / Earlier use the Baku calendar. `.stagger-item` is kept on each row (the e2e specs click it).
- **Push on this device**: only from a tap. Order: `Notification.requestPermission()` (first await, keeps the user gesture for iOS) -> register `/sw.js` -> `pushManager.subscribe({ userVisibleOnly, applicationServerKey })` -> `save_push_subscription(..., 'guest')` -> `set_notification_prefs({ push_enabled: true, language })`. Off: `delete_push_subscription`, unsubscribe, and `push_enabled: false` only when `push_subscriptions` shows no other device left. A key rotation (`applicationServerKey` changed) re-subscribes. No `VITE_VAPID_PUBLIC_KEY` = no push UI at all; iOS Safari not installed = the "Add Rufesto to your Home Screen" note instead of the switch.
- **Prompts**: `maybeAskForPush('order'|'booking')` shows only when signed in, push is possible here, permission is not `denied`, push is not already on, and that kind was never shown on this device (`localStorage rufesto_push_prompt_<kind>`, written the moment it shows; blocked storage = never shown). A card under the header, 1.2 s after the confirmation.
- **sw.js** push body (JSON): `{ title, body, url, tag, icon, badge }` (also `image`, `id`). Always shows a notification (even for a body it cannot parse; Safari revokes silent subscriptions). `tag` replaces instead of stacking (`renotify`). Click: closes it, focuses an open tab and asks it to navigate (`postMessage` + reply port, so the SPA routes without a reload; an old tab without the listener gets `client.navigate`), else `clients.openWindow(path)`. Only the path + query + hash of `url` is used, on the worker's own origin, so one build works on preview and prod. No fetch handler, no caching.

## Before sql/64 (PGRST202)
Each RPC remembers once per page load that it answered "function not found". Then: the inbox reads the `notifications` table (staff types hidden, likes / comments of the same post collapsed client side, 48 h), the bell counts unread guest rows, tapping updates `read` on the table, the settings page shows its switches disabled with a note, and `enablePush` reports "not available yet". Each missing RPC costs one 404 in the console, once.

## Open points for the other agents
- `quiet_from` / `quiet_to` are sent as wall-clock `HH:MM` with no zone: the server should read them in Asia/Baku (the clock every time in the app uses), or the contract should add a zone.
- `payload` keys the client reads, besides the documented ones: `dish_name` (review_like / review_reply / review_received), `dishes` (array of names, max 3) for `order_ready`, `restaurant_name` / `restaurant_slug` / `restaurant_logo` / `post_id` for `place_post`, `starts_at` + `restaurant_name` for `booking_reminder`, `ingredient` for `stock_alert`, and for a thumbnail one of `thumbnail`, `photo_url`, `photo`, `dish_photo`, `image_url` (a full URL, or a `post-photos` path that the page signs).
- `target.kind` values mapped: `post`, `user`, `friends`, `booking`, `invite`, `bill` / `receipt`, `table` / `order`, `restaurant`, `dish`, `review` (with `payload.dish_id`). An unknown kind with a `slug` opens the restaurant.
- Not covered: `pushsubscriptionchange` (a browser that silently rotates the endpoint is re-saved the next time the guest toggles the switch).

## How it was checked
Playwright (Chromium) against `vite` on 127.0.0.1 with the Supabase project mocked (fake session in localStorage, no real account): inbox in dark / light, 360 / 390 / 430 px and desktop, en + az, no horizontal overflow, every control >= 44 px, tap = mark ids + navigate, mark all, filters, empty states, error, signed out, pre-sql/64 fallback, prefs (switches, quiet hours, denied, iOS), live badge over a mocked realtime socket, the contextual prompt (once per device, denied = none), and `sw.js`: fake push -> notification (tag replace, bad body), click -> same-document navigation, no tab -> `openWindow`. Not testable headless: a real `pushManager.subscribe` (no push service), so that step is for a phone with the real key.
